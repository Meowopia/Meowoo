# Meowoo 产品升级路线

Meowoo（喵呜）面向视频、漫画与小说，目标是让用户方便地发现内容、继续观看或阅读，并在不同设备上保持一致体验。扩展源、解析和 NAS 是提供内容的能力，不应成为首页的主体。

本路线描述目标，不代表对应功能已经发布或通过实机验收。当前以 Miru Alpha 与 Core 为基础；保留上游授权声明。

## 第一优先级：稳定、可信

- 播放与阅读：验证加载、重试、切集、切线路、退出、前后台与进度恢复；旧请求不能串入新会话。
- 数据：历史、收藏、设置不能因网络失败、乱序回包或重建而丢失；删除行为必须与提示范围一致。
- 错误状态：区分无内容、来源不可用、网络故障和权限问题；不能把请求失败伪装成空媒体库。
- 验收标准：可安装的测试包和实际设备操作，不以静态检查、接口返回或单个编译测试代替可用性验收。

## 第二优先级：像内容应用，而不是工具箱

| 方向 | 升级目标 |
| --- | --- |
| 首页 | 内容卡片、继续观看、最近更新；番剧、短剧、电影、综艺、电视剧等分类以实际来源能力提供，不堆假推荐或虚构热度。 |
| 详情页 | 统一封面、简介、选集、线路、收藏和播放入口；显示明确的来源及可用状态。 |
| 播放器 | 视频复用统一控制与错误处理，逐步覆盖字幕、音轨、倍速、画面比例及稳定续播。 |
| 我的 | 个人资料、历史、收藏、下载、皮肤与设置各有清晰职责；未连接账号或云存档时明确显示状态。 |
| 皮肤 | 从配色扩展为背景、卡片、头像框、图标与导航装饰；兼容明暗模式、大字体和无障碍，不改变操作语义。 |
| 平板 / TV | 大屏分区与焦点导航，不简单放大手机页面；TV 同时考虑遥控器和触屏。 |

沿用当前导航，优先统一页面内容与交互，不把本路线当作再次改导航的授权。装饰素材采用原创或明确获得授权的资源。

## 第三优先级：内容与设备能力

- 换源：优先稳定作品/单集标识及可解释匹配；不只凭标题合并，不在切源后悄悄播放错误集数。
- 自定义源：区分导入、格式检查、安装、启用和真正可播放；显示适配能力与错误原因。
- 媒体服务器：先完善现有 Jellyfin 基础接入，再评估 WebDAV、SMB、Emby、Plex 与飞牛，分别定义认证及播放路径。
- 磁力 / BT：验证选文件、缓冲、取消与缓存清理，按平台能力开放；解析成功不等于播放可用。
- 字幕：界面语言、字幕与音轨语言独立；自动翻译独立开关，说明联网、隐私和可能的服务费用。
- 账号与同步：采用 OO 身份方向；先确定客户端身份、回调与共存策略，再验证登录、刷新、撤销、冲突和账户数据隔离。
- 扫码登录（规划中）：Windows、macOS、Linux、平板和 TV 可展示登录二维码与确认码，手机扫码后明确批准；提供链接与手动输入码的备用路径。各类终端使用经注册的独立客户端身份，二维码失效、被拒绝或用户取消后不继续轮询，不把“扫码”当成“已登录”。
- 内容控制：默认关闭限制内容入口，启用时明确确认；关闭后撤销进行中的会话，不默认混入普通推荐和云同步。

## 平台与语言

产品目标覆盖 Android 手机/平板/TV、iOS/iPadOS、Windows、macOS、Linux 与原生 HarmonyOS NEXT，不规划 Web 客户端。目标平台不等于已经交付；原生鸿蒙需要单独验证插件与平台桥接，不能以安装 APK 代替。

当前界面语言资源包括简体中文与 English；其他主流语言按翻译质量和各端布局验收逐批交付。测试窄屏、大字号、长文本及从右向左布局，不只增加语言文件。

## 当前能力边界

- 本地皮肤包、我的页面入口、公开演示源与 Jellyfin 基础接入已有代码，仍需构建和设备验收。
- Kazumi 规则目前是导入检查与预览，不是已经具备完整运行能力。
- OO 客户端登录与跨设备云存档未完成端到端接入；不展示虚构账号、会员或同步成功状态。
- Core 当前历史删除接口按来源包与单集 URL 删除，尚不是按作品/记录 ID 精确删除；分类清空需要新接口才能安全实现，不能转成全量清空。
- 更完整的装扮皮肤、额外媒体服务器及新增平台按上面的验收条件推进，不标记为已支持。
